Deploying Your Django Apps to Google Cloud

Your VM runs one Postgres database, one reverse proxy (Caddy), and up to five Django apps — each on its own subdomain with automatic HTTPS. You develop with SQLite on your laptop and deploy with git push + one command.

Prerequisites

  • A Google Cloud account with access to a billing account
  • The gcloud CLI installed
  • A domain name (as created earlier in the semester for free via the GitHub Student Developer Pack)
  • Your Django app(s) pushed to a Git repo you can clone on the VM
Before you begin: Enter your JMU eID and domain name in the fields at the top of this page. The commands throughout will update with your values so you can copy and paste them directly.

1. Prepare your apps for deployment

Do this on your laptop, in each app’s repo, before touching Google Cloud.

Add production dependencies

Production needs a Postgres driver and a WSGI server that your laptop doesn’t. Put them in a prod dependency group so they only install inside the Docker image:

uv add --group prod "psycopg[binary]" gunicorn

For locallibrary (which includes Channels for chat), also add Daphne:

uv add --group prod daphne

Update settings.py

In each app’s settings.py, replace the DATABASES dict and add the environment helpers. Near the top of the file, after the existing imports:

import environ

env = environ.Env()

DATABASES = {
    "default": env.db(default=f"sqlite:///{BASE_DIR / 'db.sqlite3'}")
}

This gives you SQLite on your laptop (no setup, no Postgres install) and Postgres on the server (configured automatically by Docker Compose via the DATABASE_URL environment variable).

Also replace ALLOWED_HOSTS and CSRF_TRUSTED_ORIGINS:

ALLOWED_HOSTS = env.list("ALLOWED_HOSTS", default=["localhost", "127.0.0.1"])
CSRF_TRUSTED_ORIGINS = env.list("CSRF_TRUSTED_ORIGINS", default=[])

Finally, add the proxy header so Django knows requests arrive over HTTPS:

SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")

Without this line, you will get CSRF errors on login and redirect loops if SECURE_SSL_REDIRECT is on.

Add a Dockerfile

Copy Dockerfile.example into each app’s repo as Dockerfile. The only line you need to change is the last one — replace the module name with your app’s WSGI or ASGI module.

For locallibrary (which uses Daphne for Channels):

CMD ["sh", "-c", "python manage.py migrate --noinput && exec daphne -b 0.0.0.0 -p 8000 locallibrary_config.asgi:application"]

For kahduke and other apps without Channels:

CMD ["sh", "-c", "python manage.py migrate --noinput && exec gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 YOUR_APP.wsgi"]

Commit and push

Make sure everything still works locally (uv run python manage.py runserver), then commit and push:

git add pyproject.toml uv.lock Dockerfile settings.py
git commit -m "Add production config for Google Cloud deployment"
git push

Repeat for each app. From here on, everything happens in Google Cloud.

2. Create your Google Cloud project

Authenticate and create a project. Use cs347f26-YOUR_EID as the project ID:

gcloud auth login
gcloud projects create cs347f26-YOUR_EID --name="CS 347 - YOUR_EID"
gcloud config set project cs347f26-YOUR_EID

Then link your billing account so you can enable Compute Engine. List your billing accounts to find the ID:

gcloud billing accounts list

Copy the account ID (format XXXXXX-XXXXXX-XXXXXX) and enter it in the “Billing Account ID” field above, then link it to your project (you probably want the one whose name is Billing Account for Education):

gcloud billing projects link cs347f26-YOUR_EID --billing-account=BILLING_ACCOUNT_ID

3. Create your VM

Clone this repository and run the setup script with your JMU eID:

git clone https://github.com/CS-347-F26/google-cloud.git
cd google-cloud
./create-vm.sh YOUR_EID

The script creates a static IP address, opens ports 80 and 443, and launches a Debian VM that installs Docker automatically on first boot. It prints your static IP when it finishes — enter it in the “Static IP” field above. The DNS and SSH commands below will update with your IP.

Wait about 60 seconds for the startup script to finish installing Docker. You can watch it:

gcloud compute ssh cs347-YOUR_EID --zone us-central1-c \
  --command 'sudo journalctl -u google-startup-scripts -f'

4. Set up DNS

At your domain registrar, add one wildcard A record:

*.yourdomain.dev    A    YOUR_STATIC_IP
Important: The IP address from step 2 should not start with 10. — that is an internal IP. Use the external IP that the script printed.

This single record covers every app you will ever add. Verify it resolves before continuing:

dig +short library.yourdomain.dev

You should see your static IP. If it returns nothing, wait a few minutes and try again. Do not start the containers until DNS is working — Caddy requests a TLS certificate on first contact with each hostname, and that fails if DNS is not live yet.

5. SSH into your VM

gcloud compute ssh cs347-YOUR_EID --zone us-central1-c

The first time you log in, the VM adds you to the docker group. Log out and back in once for that to take effect:

exit
gcloud compute ssh cs347-YOUR_EID --zone us-central1-c

Verify Docker works without sudo:

docker ps

You should see something like:

CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES

Set up SSH config for direct access

gcloud compute ssh works, but you can also configure plain ssh, scp, and rsync to connect directly. First, find your OS Login username:

gcloud compute os-login describe-profile --format='value(posixAccounts[0].username)'

It will look something like stewarmc_jmu_edu. Paste it into the “OS Login Username” field above.

Add an entry to ~/.ssh/config on your laptop:

Host cs347-YOUR_EID
    HostName YOUR_STATIC_IP
    User YOUR_OS_LOGIN_USERNAME
    IdentityFile ~/.ssh/google_compute_engine

Now you can use standard tools from your laptop, e.g.:

  • Get an interactive terminal: 
    ssh cs347-YOUR_EID
  • Copy files to the VM: 
    scp WHATEVER_FILES cs347-YOUR_EID:/whatever/path/
  • Or sync an app directory: 
    rsync -av WHATEVER_DIR/ cs347-YOUR_EID:/WHATEVER_REMOTE_DIR/

FYI: The key at ~/.ssh/google_compute_engine was created by your first gcloud compute ssh.

6. Clone the deployment files and your apps

Copy the deployment files (Dockerfile.example, docker-compose.yml, Caddyfile, init-databases.sql, env.example) into /srv/apps/. By running the following form your laptop:

scp Dockerfile.example docker-compose.yml Caddyfile init-databases.sql env.example cs347-YOUR_EID:/srv/apps

Next ssh to the server and move to the directory where you just put those files

ssh cs347-YOUR_EID
cd /srv/apps

Then clone your Django apps beside them:

git clone YOUR_LOCALLIBRARY_REPO locallibrary
git clone YOUR_KAHDUKE_REPO kahduke

Your /srv/apps/ directory should look like this:

/srv/apps/
  .env ← you create this next
  Caddyfile
  Dockerfile.example
  docker-compose.yml
  env.example
  init-databases.sql
  kahduke/ ← your app repo
  locallibrary/ ← your app repo

7. Configure your environment

cp env.example .env
nano .env

Fill in your values:

VariableWhat to put
SECRET_KEYA long random string (run python3 -c "import secrets; print(secrets.token_urlsafe(50))")
ACME_EMAILYour email (for Let’s Encrypt expiry warnings)
LOCALLIBRARY_HOSTlibrary.yourdomain.dev
KAHDUKE_HOSTkahduke.yourdomain.dev
FINAL_PROJECT_HOSTfinalproject.yourdomain.dev
ALLOWED_HOSTS.yourdomain.dev
CSRF_TRUSTED_ORIGINShttps://*.yourdomain.dev
POSTGRES_PASSWORDA strong password (only used internally between containers)

Do not set DATABASE_URL in .env. Leaving it unset is what makes SQLite work on your laptop.

8. Start everything

docker compose up -d --build

This builds your app images, starts Postgres, runs your migrations, and starts Caddy. On first launch it takes a few minutes because it is downloading base images and building from scratch.

Check that everything is running:

docker compose ps
docker compose logs -f

Once Caddy has obtained certificates (you will see log lines about it), visit your apps:

  • https://library.yourdomain.dev
  • https://kahduke.yourdomain.dev

Deploying updates

After pushing changes to your app’s repo:

gcloud compute ssh cs347-YOUR_EID --zone us-central1-c
cd /srv/apps
git -C locallibrary pull
docker compose up -d --build locallibrary

Migrations run automatically on container start, so there is no separate step for that.

Adding a fourth app

Four things, in order:

  1. docker-compose.yml — add a service stanza (copy the final_project block, change the name and build path)
  2. Caddyfile — add a {$APP4_HOST} block
  3. .env — add APP4_HOST=app4.yourdomain.dev
  4. Create the database — the init-databases.sql file only runs on the very first Postgres start, so create it by hand:
docker compose exec postgres createdb -U cs347 app4

Then docker compose up -d --build.

Backups

Dump all your databases to a file:

docker compose exec postgres pg_dumpall -U cs347 > ~/backup-$(date +%F).sql

The Postgres data volume survives docker compose down, reboots, and rebuilds. It does not survive docker compose down -v — that flag deletes all volumes, including your databases. Do not use it.

Troubleshooting

ProblemLikely cause
CSRF errors on loginMissing SECURE_PROXY_SSL_HEADER in settings.py
Infinite redirect loopSECURE_SSL_REDIRECT = True without SECURE_PROXY_SSL_HEADER
TLS / certificate errorsDNS not resolving yet, or port 80 is blocked
Killed during docker compose buildThe swap file is missing — check that the startup script ran
Browser refuses plain HTTP.dev domains are HSTS-preloaded; you must use https://
New database not created after editing init-databases.sqlThat file only runs once; use docker compose exec postgres createdb -U cs347 dbname

Tearing down

When the semester is over, the cleanest way to remove everything is to delete the entire project:

gcloud projects delete cs347f26-YOUR_EID

This removes the VM, disk, and static IP in one step.
